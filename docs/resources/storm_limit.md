# tplinkeasysmart_storm_limit (Resource)

Storm control of one port (QoS > Storm Control). Selecting traffic types requires a rate (64..1000000 kbps, multiple of 64); selecting none disables it with rate 0. Import with the port number. **Safety:** a rate drops excess traffic of the chosen types, so by default the provider refuses to change a port that has a link up or is in a LAG; set `allow_disruptive = true` to override. Destroying only removes it from state.

~> **Safety** A rate drops excess traffic of the selected types. The provider refuses to change a port that has a link up or belongs to a LAG unless `allow_disruptive = true`.

## Example Usage

```terraform
resource "tplinkeasysmart_storm_limit" "unused" {
  port      = 7
  broadcast = true
  multicast = true
  rate_kbps = 1024 # multiple of 64; required when a traffic type is selected

  # Safety: by default the provider refuses to change a port that has a link up
  # or belongs to a LAG, because that can cut the uplink or the management path.
  # Only set this after checking the port is not needed for connectivity.
  # allow_disruptive = true
}
```

## Schema

### Required

- `port` (Number) Port number (1-based).

### Optional

- `allow_disruptive` (Boolean) Allow changing a port that has a link up or is a LAG member. Defaults to false.
- `broadcast` (Boolean) Limit broadcast traffic.
- `multicast` (Boolean) Limit multicast traffic.
- `rate_kbps` (Number) Rate in kbps (multiple of 64, 64..1000000) when a traffic type is selected, otherwise 0.
- `switch` (String) Name of the switch (a key of the provider's `switches` map) this object lives on. Omit it to use the provider's own switch (`host`), or the only configured switch. Changing it replaces the resource.
- `unknown_unicast` (Boolean) Limit unknown unicast traffic.

## Import

Import is supported using the following syntax:

```shell
# The import id is the port number.
terraform import tplinkeasysmart_storm_limit.unused 7
```

For a switch defined in the provider's `switches` map, put the switch name in front of the id, separated by a colon (for example `sw02:7` or `sw02:led`). Without a prefix the id belongs to the provider's own switch (`host`).
