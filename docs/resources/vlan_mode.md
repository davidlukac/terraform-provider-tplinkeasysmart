# tplinkeasysmart_vlan_mode (Resource)

The VLAN mode of the switch (VLAN > MTU VLAN, Port Based VLAN, 802.1Q VLAN): exactly one of the three is active. Singleton; import with id `vlan_mode`. **Safety:** switching the mode discards the VLAN settings of the other modes and can cut every connection, including the management path, so the provider refuses to change the mode unless `allow_disruptive = true`. Applying the mode the switch already has writes nothing. Destroying only removes it from state.

~> **Safety** Switching the VLAN mode discards the VLAN settings of the other modes (the vendor utility warns about this) and can cut every connection, including the management path. The provider refuses to change the mode unless `allow_disruptive = true`; applying the mode the switch already has writes nothing. Do it on a switch you can reach another way, with a fresh configuration backup (`tplinkeasysmart_config_backup`). On the verified firmware (20250710), enabling `802.1q` created VLAN 1 with every port untagged and PVID 1, so the management path through the uplink stayed up; going back to `port-based` restored the port-based VLAN 1 with all ports. The MTU VLAN was exercised live on the same firmware (uplink port 1, switched on and back to `port-based`): the management path through the uplink stayed up. With it on, only the uplink port can talk to the others, so a wrong `mtu_uplink_port` cuts the management path. Switching back leaves one byte of the stored MTU settings changed in the configuration file; the switch itself is back to its previous state.

## Example Usage

```terraform
# Exactly one VLAN mode is active: "mtu", "port-based" or "802.1q". Changing it
# discards the VLAN settings of the other modes and can cut every connection,
# including the management path, so the provider refuses unless it is allowed.
# Applying the mode the switch already has writes nothing.
resource "tplinkeasysmart_vlan_mode" "this" {
  mode = "802.1q"

  # Needed for the change itself; remove it again once the switch is in the mode.
  allow_disruptive = true
}

# The MTU VLAN needs its uplink port: every other port can only talk to it.
# resource "tplinkeasysmart_vlan_mode" "this" {
#   mode            = "mtu"
#   mtu_uplink_port = 8
# }
```

## Schema

### Required

- `mode` (String) One of `mtu`, `port-based` or `802.1q`.

### Optional

- `allow_disruptive` (Boolean) Allow changing the VLAN mode. Defaults to false.
- `mtu_uplink_port` (Number) The uplink port of the MTU VLAN: every other port can only talk to it. Required with `mode = "mtu"`, not allowed with another mode.
- `switch` (String) Name of the switch (a key of the provider's `switches` map) this object lives on. Omit it to use the provider's own switch (`host`), or the only configured switch. Changing it replaces the resource.

### Read-Only

- `id` (String) Always `vlan_mode`.

## Import

Import is supported using the following syntax:

```shell
# The import id is always vlan_mode.
terraform import tplinkeasysmart_vlan_mode.this vlan_mode
```

For a switch defined in the provider's `switches` map, put the switch name in front of the id, separated by a colon (for example `sw02:7` or `sw02:led`). Without a prefix the id belongs to the provider's own switch (`host`).
