# tplinkeasysmart_lag (Resource)

A link aggregation group (Switching > Port Trunk). Import with the group number. **Safety:** the provider refuses to create, change or destroy a group when any port involved (old or new members) has a link up or belongs to another LAG, because that can cut the uplink; set `allow_disruptive = true` to override. The existing router uplink (usually LAG1) should be imported and protected with `lifecycle { prevent_destroy = true }`. The group number decides the ports: LAG 1 takes ports 1-4 and LAG 2 takes ports 5-8, each with 2 to 4 members. The switch itself rejects ports that conflict with the port mirror (source or destination), a port-based VLAN other than the default, a bandwidth limit or storm control, and member ports that differ in speed, flow control or enabled state, mix auto-negotiation with a fixed speed, are half duplex or (in port-based QoS mode) differ in QoS priority; the error then names the conflict. The switch checks this only when the group is written and does not keep the members alike afterwards, so change the members together.

~> **Safety** The provider refuses to create, change or destroy a group when any port involved (old or new members) has a link up or belongs to another LAG. Import the group that carries the router uplink and protect it with `lifecycle { prevent_destroy = true }`. 

~> **Which ports go where** The TL-SG108E has two LAG groups with fixed port ranges: group 1 takes ports 1-4 and group 2 takes ports 5-8, with two to four members each. A group that mixes ranges (for example group 1 with ports 4 and 5) is refused by the switch, so the provider refuses it while planning. Verified on firmware 20230218 and 20250710.

~> **Ports the switch refuses** A port that is mirrored or is the mirror destination, belongs to a port-based VLAN other than the default one, has a bandwidth limit or has storm control cannot join a LAG. The switch answers with an error code and the provider names the conflict; nothing is changed. Remove the conflicting setting first.

## Example Usage

```terraform
# A second group from two free ports. Never change the group that carries the
# uplink to the router without a way back to the switch.
resource "tplinkeasysmart_lag" "spare" {
  group = 2
  ports = [6, 7]
}

# Import the existing uplink and protect it.
resource "tplinkeasysmart_lag" "uplink" {
  group = 1
  ports = [1, 2]

  lifecycle {
    prevent_destroy = true
  }
}
```

## Schema

### Required

- `group` (Number) Group number: 1 (ports 1-4) or 2 (ports 5-8).
- `ports` (Set of Number) Member ports: 2 to 4, all within the range of the group (group 1: ports 1-4, group 2: ports 5-8).

### Optional

- `allow_disruptive` (Boolean) Allow touching ports that have a link up or belong to a LAG. Defaults to false.
- `switch` (String) Name of the switch (a key of the provider's `switches` map) this object lives on. Omit it to use the provider's own switch (`host`), or the only configured switch. Changing it replaces the resource.

## Import

Import is supported using the following syntax:

```shell
# The import id is the LAG group number.
terraform import tplinkeasysmart_lag.uplink 1
```

For a switch defined in the provider's `switches` map, put the switch name in front of the id, separated by a colon (for example `sw02:7` or `sw02:led`). Without a prefix the id belongs to the provider's own switch (`host`).
