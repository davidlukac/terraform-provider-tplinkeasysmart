# tplinkeasysmart_system (Resource)

System settings (System > System Info > Device Description). Singleton; import with id `system`. Only the device description is managed. This resource never changes the management IP, DHCP or gateway (the request re-sends them as read from the switch); `tplinkeasysmart_management_ip` manages them. A write is skipped when the description already matches. Destroying only removes it from state.

## Example Usage

```terraform
# The device description: letters, digits and hyphens only (no dots or underscores).
# The management IP, DHCP flag and gateway are re-sent unchanged and never modified here
# (tplinkeasysmart_management_ip manages them).
resource "tplinkeasysmart_system" "this" {
  hostname = "sw01"
}
```

## Schema

### Required

- `hostname` (String) Device description: 1-32 letters, digits and hyphens, not starting or ending with a hyphen (dots and underscores are rejected by the switch).

### Optional

- `switch` (String) Name of the switch (a key of the provider's `switches` map) this object lives on. Omit it to use the provider's own switch (`host`), or the only configured switch. Changing it replaces the resource.

### Read-Only

- `id` (String) Always `system`.

## Import

Import is supported using the following syntax:

```shell
terraform import tplinkeasysmart_system.this system
```

For a switch defined in the provider's `switches` map, put the switch name in front of the id, separated by a colon (for example `sw02:7` or `sw02:led`). Without a prefix the id belongs to the provider's own switch (`host`).
