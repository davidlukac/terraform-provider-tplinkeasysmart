# TP-Link Easy Smart Provider

Manages TP-Link Easy Smart switches (TL-SG108E v6) over their native UDP management protocol. The provider must run on the same layer-2 network as the switches. Configure one switch with `host`, `username` and `password` (use a provider alias per switch), or any number with the `switches` map and select one per resource with `switch`. Do not run two clients against the same switch at once.

## Requirements

- Terraform 1.4 or later, or OpenTofu (the provider is signed and published on both registries).
- The machine that runs Terraform must be on the **same layer-2 network** as the switches: the management protocol is UDP broadcast based.
- Hardware: TL-SG108E v6 is the tested model; see the [compatibility table](https://github.com/davidlukac/terraform-provider-tplinkeasysmart#compatibility) for the firmware builds that are verified. On any other build the provider refuses writes unless `allow_unverified_firmware = true`; reads always work.

## Safety

These switches have **no console**, and the management protocol has **no real security on the wire** (its keys are public or trivially breakable): keep the switches on a trusted management network. A write that cuts the management path (a wrong address, VLAN or uplink) can only be undone with a physical factory reset. The provider therefore refuses the risky changes by default (`allow_disruptive`), never changes the user account, restores a configuration, reboots, resets or upgrades a switch, and has no telemetry. Take a configuration backup (`tplinkeasysmart_config_backup`) before the first write to a switch you cannot reach another way.

Only one client may talk to a switch at a time; Terraform's state lock does not protect the switch.

## Several switches

With a `switches` map every resource and data source must set `switch`; `default` names the provider's own switch (`host`) beside the map. Ids of a named switch are prefixed with its name (`sw02:led`); the own switch keeps plain ids. This id format is stable.

## Stability

Semantic versioning; from 1.0.0 a breaking change needs a major version and is deprecated for at least one minor version first. See the [README](https://github.com/davidlukac/terraform-provider-tplinkeasysmart#stability).

## Example Usage

```terraform
terraform {
  required_providers {
    tplinkeasysmart = {
      source = "davidlukac/tplinkeasysmart"
    }
  }
}

variable "switch_host" {
  type        = string
  description = "Management IP address of the switch (same layer-2 network as the machine running Terraform)."
}

variable "switch_username" {
  type = string
}

variable "switch_password" {
  type      = string
  sensitive = true
}

provider "tplinkeasysmart" {
  host     = var.switch_host
  username = var.switch_username
  password = var.switch_password

  # Seconds to wait for a reply before retrying a request (default 3).
  # timeout_seconds = 3

  # Writes are refused on firmware builds this provider version was not
  # verified against (reads and imports always work). Opt in at your own risk
  # (or export TPLINK_EASYSMART_ALLOW_UNVERIFIED_FIRMWARE=true):
  # allow_unverified_firmware = true
}

# Alternatively leave the provider block empty and export
# TPLINK_EASYSMART_HOST, TPLINK_EASYSMART_USERNAME and TPLINK_EASYSMART_PASSWORD.

# Name the switch by its MAC address when its IP address may change (DHCP, a move).
# `mac` pins the identity, so a different device at `host` is never written to; without
# `host`, or when `host` does not answer, the switch is found by a layer-2 discovery on
# the first request (about half a second). The data source tplinkeasysmart_system_info
# reports the value as `mac_address`.
#
# provider "tplinkeasysmart" {
#   mac      = "00:00:5e:00:53:01"   # or TPLINK_EASYSMART_MAC
#   username = var.switch_username
#   password = var.switch_password
# }

# Several switches: use the `switches` map and select one per resource with
# `switch = "<name>"` (see examples/multi-switch), or declare one provider
# alias per switch.
```

## Schema

### Optional

- `allow_unverified_firmware` (Boolean) Write to switches whose firmware build this provider version was not verified against. Defaults to false: reads and imports always work, but every write is refused on an unverified build, because a newer firmware may have changed the protocol. Verified builds: 20230218, 20250710. Falls back to TPLINK_EASYSMART_ALLOW_UNVERIFIED_FIRMWARE (`true` or `false`). Can be overridden per switch in the `switches` map.
- `host` (String) IPv4 address or hostname of the switch. Falls back to TPLINK_EASYSMART_HOST. Optional when `mac` is set.
- `mac` (String) MAC address of the switch (`aa:bb:cc:dd:ee:ff`, colons or hyphens, any case; `system_info` reports it as `mac_address`). It pins the identity: a device with another MAC at `host` is never written to. Without `host`, or when `host` does not answer, the switch is found by a layer-2 discovery on the first request, so its address may change (for example under DHCP). Discovery needs the same layer-2 segment; use `host` as well when Terraform runs elsewhere. Falls back to TPLINK_EASYSMART_MAC.
- `password` (String, Sensitive) Admin password. Falls back to TPLINK_EASYSMART_PASSWORD.
- `switches` (Attributes Map) Switches managed by this provider, by name. Select one on a resource or data source with `switch = "<name>"`. May be combined with `host`, which then names the default switch used when `switch` is omitted. (see [below for nested schema](#nestedatt--switches))
- `timeout_seconds` (Number) Seconds to wait for a reply before retrying a request, 1 to 30 (the longest the library takes). Defaults to 3.
- `username` (String) Admin user name. Falls back to TPLINK_EASYSMART_USERNAME.
