# Contributing

Issues and pull requests are welcome. Open an issue first for a new setting. This page is the checklist for **any change to the client, a resource or a data source**. Tick every line that applies, or write in the pull request why it does not. The short version of the pull request checklist is in `.github/pull_request_template.md`; this is the full one.

Tags: **[C]** client change (the [escp-go](https://github.com/davidlukac/escp-go) library; see the first item of section 0), **[R]** new or changed resource, **[D]** new or changed data source. A line without a tag applies to all three.

## 0. Before you start

- [ ] **Route your change.** Find it in the [routing table of the defect classes](contributing/defect-classes.md#routing-which-entries-does-my-change-touch) and answer the DESIGN question of each entry it names in the issue or the pull request (a sentence is enough). A change to a schema, an id, a documented behavior or a write path also gets the questions of the [adversarial review](contributing/adversarial-review.md) before it is written. The lines below that carry a class id are the mechanical side of that class: the class says what to ask and test, this page says how.
- [ ] Run `make hooks` once per clone. The pre-commit hook runs format, vet, lint, tests with `-race` and the coverage policy, and must never be bypassed. It does **not** run the Terraform scenarios of `internal/regression`: they skip unless `TF_ACC=1` is set (a skipped scenario still reports `ok`), and CI runs them with `make testacc`. Run `make regression` yourself before you push (about two minutes; needs `terraform` on the `PATH`).
- [ ] **Write American English** in code (exported names included), comments, documentation, Terraform descriptions, commit messages and pull requests: `behavior`, `canceled`, `color`, as the Go standard library and godoc spell them (`cancellation` is fine). The `misspell` linter (locale US) checks the Go files in the pre-commit hook and in CI ([DC-C08](https://github.com/davidlukac/escp-go/blob/main/docs/defect-classes.md#dc-c08)).
- [ ] Work on a branch (`feat/`, `fix/`, `docs/`, `test/`, `chore/`). Nothing goes to `main` directly.
- [ ] Decide the kind of change, because it drives the version: a new setting or resource is `feat` (minor); a bug fix is `fix` (patch); a change that only touches tests, docs, CI or internals is `test:`/`docs:`/`ci:`/`refactor:`/`chore:` and does not release by itself.
- [ ] **[R]** Can the change cut management access or break traffic? Then it needs a guard and an `allow_disruptive` argument, and it is designed with the safety notes in the README (*Safety by design*) in mind. Settings that can lock you out of the switch (credentials, reboot, factory reset, config restore, firmware) are deliberately not writable.
- [ ] **A change that needs a library change** (a new setting, a changed write) is two cycles: first a pull request and a release in the [escp-go](https://github.com/davidlukac/escp-go) repository, then this one, which requires that release in `go.mod` (`go get github.com/davidlukac/escp-go@vX.Y.Z`; never a pseudo-version on `main`). To develop both at once, `make work` links this checkout to `../escp-go` (a local `go.work`, not committed; `make unwork` removes it) and so does the `go build` that produces the binary `scripts/tf.sh` runs. The pre-commit hook ignores the workspace, so a commit is checked against the released version, as CI will.

## 1. Code

**Client** (a library change: its checklist is [escp-go's CONTRIBUTING.md](https://github.com/davidlukac/escp-go/blob/main/CONTRIBUTING.md): setting file layout, wire layout in `PROTOCOL.md`, named protocol numbers, value types, validation, the write gate, read-back, documentation, fuzz targets, wire tests against `escptest`)

**Provider (`internal/provider`)**

- [ ] **[R][D]** The method is added to `SwitchClient` (`client.go`); the resource or data source declares the small interface it actually needs.
- [ ] **[R][D]** The type is registered in `provider.go` (`Resources()` / `DataSources()`), with the file named `<name>_resource.go` or `<name>_data_source.go`.
- [ ] **[R][D]** Schema: snake_case names, a `Description` on every attribute, the right mode (Required / Optional+Computed / Computed), the `switch` argument for the multi-switch model (resources: `resourceSwitchAttribute()`), no volatile values in resources (counters belong in data sources); the same name, type and spelling as the closest existing attribute ([DC-P05](contributing/defect-classes.md#dc-p05)).
- [ ] **[R][D]** The schema snapshot is updated in the same pull request: `internal/provider/testdata/schema_snapshot.txt` lists every attribute of the provider, the resources and the data sources with what decides how it behaves (kind, required, optional, computed, sensitive, default, plan modifiers, validators, deprecation; not the descriptions). `TestSchemaSnapshotIsCurrent` fails, with the lines that changed, when the schema differs from it; when the change is meant, regenerate it with `go test ./internal/provider -run TestSchemaSnapshotIsCurrent -update-schema-snapshot` and read the diff of the file as a reviewer would: a flipped default, an attribute that became required, a lost `RequiresReplace` or a stricter validator breaks configurations that planned clean before. The snapshot does not see inside `ModifyPlan` or `ValidateConfig`; their behavior is pinned by their own tests.
- [ ] **Layering** is enforced by `make lint` (`depguard` and `forbidigo` in `.golangci.yml`): `internal/provider` does not import `net` (only `net/netip`) or `syscall` and opens no socket, product code does not import the fake switch (`escptest`), `testing` or `internal/regression`, the tools do not import the provider, a provider logs through `tflog` and not to stdout, and the environment is read in `internal/provider/env.go` only. The dependencies point from `main` to `internal/provider` to the library, and from `internal/regression` to `internal/provider`; a new import that breaks that is a design question, not a lint setting to loosen.
- [ ] **A function that reads a setting and then writes one**, and **a blocking call made while a lock is held**, are reported by `make analyzers` (part of `make lint`: the `readwrite` and `lockwait` checks of `devtools/analyzers`, configured with this repository's names in the `Makefile`). An intended case carries its reason: `// readwrite: <reason>` in the doc comment of the function (what makes a read that is stale by the time of the write harmless), `// lockwait: <reason>` on the call or the lock (what ends the wait). A new client interface keeps the names `...Client` or `...Reader` and the methods of `SwitchClient`, so the checks see its calls.
- [ ] **[R]** Plan-time validation (`ValidateConfig`, validators or `ModifyPlan`) refuses bad values before anything is applied, with the rule the apply uses. Apply-time defenses stay as a second layer ([DC-P01](contributing/defect-classes.md#dc-p01)).
- [ ] **[R]** Writes that can touch a port in use or a LAG member go through the guards (`guard.go`, `safety.CheckPorts`), refuse before any write, and honor `allow_disruptive`. Changing only `allow_disruptive` writes nothing ([DC-P03](contributing/defect-classes.md#dc-p03)).
- [ ] **[R]** The apply reads back and fails loudly ("did not change as requested") when the switch kept something else; state holds what the switch reports ([DC-P01](contributing/defect-classes.md#dc-p01)).
- [ ] **[R]** Import is supported with a documented id (qualified with the switch name for `switches`); `Read` normalises into the form the configuration uses; drift shows in the plan ([DC-P02](contributing/defect-classes.md#dc-p02)).
- [ ] **[R]** Destroy semantics are decided and documented: singletons and per-port settings only forget; groups remove their group under the same guard. Restoring a value is always an explicit configuration; create over an existing object is refused ([DC-P02](contributing/defect-classes.md#dc-p02)).
- [ ] **[R][D]** Errors name the attribute (`AddAttributeError`), the cause and the way out. Credentials are `Sensitive` and never logged.

## 2. Tests

Coverage must stay at 100% of reachable statements (`make cover`, exclusions only with `// coverage: ignore - <reason>`). A test that depends on timing is a bug: build the state deterministically. After writing a test, break the code on purpose and confirm the test fails.

- [ ] **[R][D]** Terraform lifecycle tests through a real Terraform binary against the in-memory fake client (`provider_test.go`): create, update, import (`ImportStateVerify`, with `ImportStateVerifyIdentifierAttribute` when the id differs from an attribute), drift (change the fake behind Terraform's back, expect a non-empty plan), validation errors (`ExpectError`), destroy semantics, the `switch` argument and qualified ids.
- [ ] **[R]** Guard tests: a refused write performs **zero** writes; an `allow_disruptive`-only change writes nothing; every guard sentence is asserted ([DC-P03](contributing/defect-classes.md#dc-p03)).
- [ ] **Regression fake** (`escptest/model.go` in the escp-go library, so a library change and release first): the stateful fake stores and answers the new setting, and enforces any rule the switch has (refusals, exclusivity, derived values) **as measured on hardware**. Rules that are only assumed are marked as such in a comment ([DC-C05](https://github.com/davidlukac/escp-go/blob/main/docs/defect-classes.md#dc-c05), [DC-C07](https://github.com/davidlukac/escp-go/blob/main/docs/defect-classes.md#dc-c07)).
- [ ] **Regression scenario** (`internal/regression`): a reader for the setting in `CoreReaders` (so the whole-switch readout includes it) and a scenario that changes it through Terraform, verifies it by reading the switch directly with the client, restores the original by explicit configuration (use `depends_on` and several restore steps where the order matters) and proves the readout is identical. A guard refusal gets a scenario that asserts no write. A scenario takes its ports from the target (`Target.TestPorts`), reads the original values from the switch and never assumes an address, port or initial value, so that it passes on the fake and on a real switch. Run it: `make regression` (fake, also part of `make testacc` in CI; [DC-P07](contributing/defect-classes.md#dc-p07)).
- [ ] **The scenarios are run, not just compiled.** `make regression` (that is `TF_ACC=1 go test -race -count=1 ./internal/regression/...`; add `-run TestScenarioName` for a single scenario) passes before every push that touches the client, the fake, the provider or a type the scenarios use. Without `TF_ACC=1` every scenario skips, so the pre-commit hook and a plain `go test ./...` say nothing about them. This matters most for refactors: retyping a value (a port list, an id, a rate) can leave everything compiling while a scenario that formats or compares it now builds a different configuration, which is how a retyping once reached CI with four scenarios failing. After such a change, search the scenarios and their helpers for `fmt.Sprint` and `%v` of the retyped values.
- [ ] **Live checks** on a switch you own, never on one you cannot afford to lose: the library's `-tags live` tests (in the escp-go repository, `ESCP_*` variables: unused port, deferred restore before the first write, restore verified) and `make regression-live CONFIRM=1` with a `.test.env` (see `.test.env.example`). Take a configuration backup first, watch pings, and keep the uplink and ports with devices out of it. Not possible for a change? Say so in the pull request.
- [ ] **Mutation testing** (`make mutation-diff` for the lines you changed, `make mutation` for the packages with fast tests; gremlins pinned in `devtools/go.mod`): a surviving mutant is a missing test (a boundary, the other branch, an argument order), fixed by a test that fails against that mutant; an equivalent mutant is explained, not contorted around ([DC-C05](https://github.com/davidlukac/escp-go/blob/main/docs/defect-classes.md#dc-c05)). The tests of `internal/provider` take about two minutes, so the pull request job runs only for a change of at most 40 lines of non-test Go code, and the weekly run covers `internal/regression`; mutate a larger change by hand, one file at a time. CI's job is informational.
- [ ] **A parser of text that comes from outside** (an environment file, a configuration value, a reply) gets a fuzz target next to its tests (`FuzzParseEnvFile` in `internal/regression` is the model): seeds that include the edge cases, an input bounded to 1 KB (a longer one runs the same code and the engine minimizes it slowly), and properties checked on the result (no panic, a refusal that quotes nothing of the input, a result that reads back the same), not only "does not crash". `go test` runs the seeds on every pull request; `make fuzz` explores further (30 seconds per target, `SECONDS=120` for longer) and the weekly `fuzz` workflow runs it too. A failing input is written to the package's `testdata/fuzz` directory: commit it with the fix.
- [ ] **A list of cases is a table of subtests**: write the cases as a slice (or map) of structs with a `name` and run each with `t.Run(tc.name, func(t *testing.T) { ... })`, never a bare `for` loop that reports with `t.Errorf` (the failure would not name its case, a `t.Fatalf` would hide the cases after it, and one case could not be run alone with `-run 'TestX/name'`). Go has no data-provider facility; this is the idiom. `make lint` runs `devtools/subtests` (a `go/analysis` check; the files in `devtools/subtests` and `devtools/analyzers` are verbatim copies of escp-go's `devtools` directories, so a change to them is made there and copied here whole, never edited by hand in this repository), which fails on a loop over cases written out in a test that never calls `t.Run`; a loop that is not a table of cases (it sets up the test, for example) says so with a `// subtests: <reason>` comment. Live tests are exempt: a failing live case has to stop before it writes more to a switch.
- [ ] `gofmt`, `go vet` (also `-tags live`), `golangci-lint`, `go test ./... -race -count=1` and `make regression` pass, and so do `make validate-examples` and `make docs-check`.
- [ ] CI is green on every Terraform version of the matrix (the OpenTofu leg is informational).

## 3. Documentation

- [ ] **[R][D]** Provider docs regenerated with `make generate` and committed; `make docs-check` clean. Safety text for a resource lives in `templates/resources/<name>.md.tmpl` (guards, destroy behavior, ordering with other resources).
- [ ] **[R][D]** An example in `examples/resources/<type>/resource.tf` (or `examples/data-sources/...`) that passes `make validate-examples` and plans against the fake switch, plus `import.sh` for a resource. `go test ./internal/provider` enforces it (`examples_test.go`): every registered type has its example, no example is left without a type, and each example is planned through real Terraform. Documentation addresses and variables only: no real IPs, MAC addresses or credentials.
- [ ] **[R][D]** The README tables are updated: *What you can manage* (resource, web UI page, guard) and, when the verified hardware or firmware changed, *Compatibility*.
- [ ] **Hardware and firmware compatibility:** the one source is [`safety/compatibility.json`](https://github.com/davidlukac/escp-go/blob/main/safety/compatibility.json) in the library. Record there (a library change and release) which hardware revision and firmware build the change was verified on, and what is only read; after bumping the module run `make compat-table` to regenerate the README table. The firmware allow-list is read from the same file: a build becomes writable without the opt-in only when a row with `"support": "verified"` names it, and only after it has really been verified on a switch.
- [ ] `CHANGELOG.md`: user-visible changes only, taken from the diff and not from memory; breaking changes and new refusals called out.

## 4. Pull request and release

- [ ] Commit messages and the PR title follow Conventional Commits (lower-case imperative subject, no trailing period). The squash commit takes the PR title.
- [ ] The PR description says what changed, what was verified (and on what), what was not, and the remaining risks.
- [ ] A fix names the defect class it belongs to, by id, and what changes so that a check catches it next time (a test in the same pull request, an entry of the [catalog](contributing/defect-classes.md) or an issue); the pull request template asks for it.
- [ ] After the squash merge, a release follows [`RELEASING.md`](RELEASING.md): `scripts/release.sh`-style bump of `main.go` and `CHANGELOG.md` on a branch, tag on `main`, push the tag, dispatch `release.yml`, then check the version on the Registry (listing, `terraform init` and `tofu init` printing the release key ID, the rendered pages; `registry-check.yml` runs the two installs).
